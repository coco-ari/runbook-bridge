# 3.0：源码与 Codex 工作区实施方案

## 目标与交付边界

在 `3.0` 分支交付两个环境插件和各自的持久会话工作区。源码由独立 CodeMinificationRepository 服务从 Git 获取；运维工具只读消费快照。Codex 直接读取本地固定版本源码，通过现有 MCP 访问运维资源。现有云配置只同步插件配置和允许同步的凭据，不保存源码。保留 2.x 数据、插件、桌面人工操作和安全契约。

本次同时完成源码服务、源码插件工作区、Codex Agent 插件工作区。完成后两个仓库分别中文提交并推送。服务器部署不属于代码推送，不在未核验服务器身份时修改线上服务。

## 用户流程

1. 管理员在源码服务登记项目、Git 凭据、分支和定时同步间隔，开启源码快照；原 ZIP 部署下载继续可用。
2. 运维工具在环境内添加“源码”插件，填写服务地址、项目 ID、项目下载密码，验证并连接。
3. 打开源码工作区，看到远端已发布版本和本地版本；用户点击更新后首次下载完整快照，以后只下载缺少的文件对象。
4. 源码工作区提供目录树、多文件标签、行号、语法高亮、文件名与全文搜索、更新进度及打开目录。只读，不编辑同步副本。
5. 同环境添加“Codex Agent”插件，选择 ChatGPT 登录或兼容 Responses 模型服务，配置模型与本机 Codex 可执行文件。
6. Codex 工作区提供会话列表、新建对话、输入草稿、流式回复、工具事件、停止/继续和审批。切换工作区不丢失会话或源码标签。
7. 创建对话时固定所选源码插件的当前快照；源码更新不改变已有对话的读取目录。新会话使用新快照。

## 源码服务协议（cmr-source/1）

保留 `GET /api/projects/:id/source/latest` 的 URL、鉴权、响应头、ZIP 内容与同步失败语义。新增路由置于 `/api/v1/projects/:id/source`，仍以项目下载密码的 Bearer 头鉴权，客户端不能指定 Git 地址、任意提交或任意服务器路径。

| 接口 | 行为 |
| --- | --- |
| `GET /head` | 只查询已发布快照、同步状态、最后检查时间及协议能力，不触发 Git |
| `GET /snapshots/:snapshotId/manifest` | 返回不可变清单，含提交、导出规则版本、文件路径/类型/权限/字节数/SHA-256、总大小、清单摘要 |
| `GET /snapshots/:snapshotId/archive` | 首次下载对应固定快照的完整包，不调用浮动的 legacy latest |
| `POST /snapshots/:snapshotId/files` | 有界批量下载目标清单中指定的文件对象；这是读取请求，不赋予修改权限 |
| `GET /events` | SSE 仅发送版本变化，客户端重新鉴权读取 head；轮询作为断线兜底 |

完整清单允许任意旧本地版本直接比较目标版本，不依赖中间差异包。文件级哈希基于实际导出字节，遵守 `.gitattributes export-ignore`；不能用原始 Git blob 列表扩大既有交付范围。协议显式定义路径、文件类型、权限、换名/删除处理和大小限制。新快照生成失败不能使成功的旧 ZIP 交付失败。

云端共享 Git 抓取及并发队列，定时任务错峰、合并、超时、退避。新功能默认关闭，管理员显式开启；迁移不自动增加 Git 负载。只在所有对象和清单落盘后原子发布 head。清单、对象及快照缓存分开保存，不把文件正文塞进频繁重写的 state.json。对象读取按项目与清单校验；清理保护发布快照、下载租约和同步任务。服务端仍只接收原有允许的 Gitee HTTPS 来源，其他 Git 平台不顺带扩大。

## 运维工具数据与插件集成

- 新插件类型 `source`、`codex` 通过插件定义、连接适配器、UI 贡献和工作区贡献注册，避免把旧三种表单枚举扩展成大分支。
- `source.target` 包含服务地址、远端项目 ID；下载密码进入凭据库。连接验证只读 head，保存编辑沿用事务和作用域失效。
- 本地源码缓存按项目/环境/插件/配置身份/快照隔离。清单验证、路径规范化、链接与跨平台名称碰撞检查在主进程执行；不信任服务返回的绝对路径。
- 更新先构造新目录，校验字节和哈希后发布本地 current 指针。失败保留当前目录；重试复用已校验对象。离线仍可浏览已下载版本。
- 旧目录按活跃源码工作区和 Codex 会话引用保留，显式清理只能删除未引用内容。
- 桌面读文件/目录/搜索走独立、受信 frame 的有界 IPC。Renderer 不直接联网，不获取源码服务凭据。
- `open_environment` 新增源码目录、快照、提交、可用状态等摘要；不新增 MCP 文件读取/搜索工具，也不返回凭据。路径仅供有本机访问能力的 Agent 使用。
- 云同步扩展新插件公开配置和凭据类型。只同步来源关联及模型连接配置，不同步源码缓存、对话、临时进程、审批或 ChatGPT OAuth 状态。

## Codex 运行与会话

采用官方 `codex app-server --listen stdio://` JSON-RPC 接口，不解析交互终端输出。初始化后调用 `account/read`、`account/login/start`、`model/list`、`thread/start|resume`、`turn/start|interrupt`，接收流式 item/turn 事件。RPC 按 ID 关联，处理背压、超时、进程退出、未知方法和取消，不能把未完成事件显示为成功。

- 可执行文件支持自动查找和显式路径，连接时检查版本/协议能力；缺失时给出安装与选择路径入口，不把“进程未安装”伪装为模型不可用。
- 使用应用隔离的 Codex 状态目录，不覆盖用户现有 CLI 配置。ChatGPT 登录由官方 browser/device 流程管理；API Key 只从本机凭据库注入进程。模型列表失败保留可编辑模型 ID。
- 自定义服务显式配置 HTTPS/受允许内网 HTTP 地址、模型、Responses 协议与 API Key，不宣称任意第三方模型兼容。
- 每会话绑定 owner、项目、环境、插件配置身份和源码快照。模型切换、进程恢复、应用重启后恢复对话须重新核验绑定。
- MCP 配置只注入本应用 Broker 接口和当前环境约束；服务端授权实际验证作用域，不依赖提示词。
- 源码路径只读；Agent 工作目录与配置凭据存储隔离。Codex 本地命令在命名权限 profile 内运行；扩大本地访问权限的请求默认拒绝，补充信息问题在工作区回答。运维权限审批仍在消息中心逐次决策。运维变更继续由现有 OperationGate/消息中心审批，不能因内置 Agent 获得人工终端权限。
- 对话输入、输出和事件保存在本机，限制事件数量与字节；凭据、认证返回值、Broker token 不进入转录、日志或 Renderer 事件。

## 实施顺序

1. 协议与方案入库，两个仓库建立隔离分支。
2. 源码服务：不可变快照存储、manifest/批量文件协议、定时任务、SSE、后台设置、legacy 回归。
3. 运维工具：协议客户端与本地快照存储、source 定义/凭据/云同步/MCP 摘要/桌面 IPC。
4. 源码阅读工作区、更新状态与通知，UI 与端到端同步验证。
5. Codex app-server 客户端、进程/认证/模型/会话/审批生命周期，codex 插件贡献。
6. Codex 对话工作区、绑定源码和运维工具，恢复与取消测试。
7. 两仓集成、文档、包内测试、完成审计后提交并推送。

## 验收矩阵

- 服务旧接口：鉴权/密码重置/停用/响应头/导出排除/失败不回旧包，现有 11 项测试继续通过。
- 增量协议：初次完整、无变化零对象、增删改/换名、跨多版本、哈希不符拒绝、路径逃逸拒绝、只允许已发布清单对象、并发发布与下载、清理、重启恢复、同步失败保留已发布快照并显示失败。
- 客户端：断线/取消/重试、不完整文件不发布、配置换目标隔离、离线浏览、工作区和对话固定版本、云同步无缓存和OAuth内容。
- MCP：准确返回本地路径/版本/作用域，无读取内容工具、凭据及跨环境访问。
- Codex：真实 JSON-RPC 子进程合同夹具覆盖初始化、登录成功/失败/取消、模型、流式 turn、停止/继续/恢复、权限批准/拒绝、未知请求、进程崩溃、会话范围、凭据不泄漏；另用可用的真实 Codex 二进制验证握手和协议。
- UI：添加/修改/验证/连接两个插件；同时打开工作区，切换不丢状态；源码高亮/搜索；对话流式/停止/审批/恢复；窄窗和主题。
- 仓库检查：CMR `npm run check`、`npm test`、浏览器 smoke；运维工具 `check`、单元测试、`test:ui`、相关专项 smoke、Windows 构建及可运行平台的包内验证，不能用单元测试代替界面与协议验证。
- 提交审计：无用户已有未提交改动、无真实地址/凭据、无生成物；中文提交；远端分支 SHA 与本地提交一致。
