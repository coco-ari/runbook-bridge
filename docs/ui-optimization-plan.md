# UI 整体优化评估与实施方案

评估基线：2026-10-01，优化前的活动 React Renderer。适用产品：供开发和运维人员使用的桌面工作台。本文在产品代码修改前完成，是本轮优化的执行依据；实施结果和验证证据追加在末尾，不回写成“优化前问题”。

## 总体结论

当前架构符合定位，已有统一的三栏资源管理、独立专业工作区、主题与尺寸 token、确认门禁和组件体系。应沿用这些基础。长时间使用的主要阻力来自少数可验证问题：详情空间被比例导航挤占；配置完成与连接状态表述混杂；正常详情重复状态；部分浅色状态文字和操作边界偏弱；目录树和结果单元格 Tab 停靠过多；长命令的“完整核对”实际被截断。

本轮确定实施 34 项：N01–N17、W01–W10、W12、D01–D06。W11 经复审确认已由公共 Button 提供工具提示，列为保留。未证明有问题的字体、背景、主要色相、卡片分隔、按钮尺寸、专业操作和功能保持现有方案。待验证项不是实施承诺，也不作为“必须优化”要求。

## 评估方法、覆盖与证据

1. 先审查产品架构和功能范围，再看模块信息密度、空间、色彩和状态，最后检查图标、按钮、组件及交互。
2. 读取全部活动 Renderer；[组件与图标清单](ui-component-inventory.md)覆盖 142 个 TSX 文件，包括组合组件。动态图标和非 TSX 模型由业务附录补充。公共组件附录逐项覆盖 38 种组件；功能附录包括正常、异常、加载和禁用状态。
3. 使用临时数据根和合成项目/环境/插件运行真实 Electron Renderer；核对深浅主题、1280×820、960×640 等场景，并用实际 Chromium 合成颜色和焦点状态补充视觉证据。没有连接真实基础设施，没有复制本地应用数据。
4. 对每项建议记录源码证据、影响、必要性、方案、验收和官方参照。行号属于优化前基线，实施后可能变化；应通过文件和代码标识符定位。
5. 成熟软件参照用于判断工作流及交互原则，不能直接证明本产品存在问题。具体尺寸、布局和文案由本产品证据决定；不照搬别人的全部能力、默认策略或视觉品牌。

评估前验证：静态检查通过；单元测试 1843 项，1840 通过、3 跳过、0 失败；基础 UI smoke 通过，82 次只读调用、0 次修改、0 次外部跳转、0 个 Renderer/无障碍失败。该记录只代表基线，不替代优化后验证。

## 整体架构评估

### 范围与执行工作流

保留“项目 → 环境 → 插件”的持久化层级。环境是操作范围；插件是服务器、数据库或缓存的连接与权限对象。管理页配置连接、权限和环境说明，专业工作区执行手动操作。返回详情保留专业会话，关闭工作区才按既有规则清理。这样的职责划分帮助用户在多个环境之间持续工作，也避免在概览页堆叠终端、SQL 和缓存编辑功能。

参照 [VS Code 工作台布局](https://code.visualstudio.com/docs/editing/getting-started/userinterface)的稳定导航/内容区域，以及 [DataGrip 连接与会话](https://www.jetbrains.com/help/datagrip/connecting-to-a-database.html)的连接与使用会话关系。借鉴稳定范围、保留会话和内容优先；本产品继续遵守自身的环境上下文和授权边界。

不新增一级导航，不重做路由，不将所有专业工作区强行压成同一版式。服务器需要目录/文档/终端，MySQL 需要 SQL/结果/事务，Redis 需要范围/Key/值；统一外壳、动作规则、颜色和状态，允许专业内容结构不同。

### 初始空间与布局持久化

N09 采用项目栏 224 px、资源栏 320 px、详情使用剩余空间的初始布局。两个 1 px 分隔线计入计算。1280 px 窗口下详情约 734 px；1920 px 下约 1374 px。资源栏拥有类型图标、长名称省略/提示、状态和操作所需的空间，同时宽屏增加的空间主要进入详情。

这是首开或无有效布局记录时的默认值；已有有效用户布局原样恢复。拖动、折叠、键盘调整、窄窗临时压缩、恢复宽窗、编辑工作区临时展开继续使用既有规则。窄窗受现有最小宽度约束，不能强制使用三块固定宽度造成溢出。默认值须通过真实 960/1280/1920 场景复核；只有确认裁剪或操作不可达时才调整，并在本文记录原因。

### 全局与局部操作

保留全局资源搜索、项目本地过滤、专业工作区内部搜索各自范围。N04 增加全局搜索的可见入口与平台快捷键提示，使已有能力可发现。目录搜索、终端搜索、SQL 编辑器搜索、Redis 内容查找仍由当前工作区处理；不抢占终端、编辑器或输入框的快捷键。

当前没有证据支持新增全局命令中心、所有工作区互通的快捷键层或统一业务状态库。以现有公共组件和局部模型完成确定问题，避免架构改造扩大回归面。

保留已有的服务器工作区、Redis 值查看器与重编辑器的按需加载边界。W06 复用编辑器不能通过静态导入把 CodeMirror 提前装入常驻管理页；加载期间保留草稿和明确占位。这个边界用于避免体验优化增加启动成本，不扩大架构改造范围。

## 配色、字体与公共组件决策

继续使用当前中性分层背景和绿色主操作色，保留深浅/系统主题。字体沿用中文系统 UI 字体与独立等宽字体：常规13 px、辅助12 px、区块标题14 px、主要页面标题16 px、控件32/28 px。现有终端、SQL与文件编辑器字体分别保持专业场景所需的设置。

[设计系统附录](ui-optimization-design-system.md)已给出实际颜色、算法和复合背景实测，以下是本轮执行规则：

- D01：浅色状态文字与弱底色/实心按钮分开承担职责。warning/info/success/danger 普通文字在实际底色至少4.5:1；保留浅色主按钮白字，实测已为5.458:1。深色已合格状态色保持。
- D02：行号等有意义且可操作的辅助文字至少4.5:1；保留次级层次，不全部变成正文色。
- D03：键盘焦点优先提高环自身浓度；补 CommandInput 的父级焦点和 TabsContent 的可见焦点。正常界面不增加常驻发光。
- D04：单独定义操作控件边界，与所在表层至少3:1。装饰卡片、表格分隔线维持弱色；不全局提亮输入填充。实施复审实测强制颜色模式下开关滑块/轨道为同色1:1，因此仅在该模式增加系统色滑块轮廓；必要性和验收见设计系统附录。
- D05：滚动滑块与弱输入填充分开，保持轨道尺寸和内层滚动结构，改善当前位置和剩余内容提示。
- D06：继续 Phosphor；动作16 px、局部紧凑14/15 px、标题/空态20 px。图标按钮有动作名；带文字的装饰图标、箭头与勾选隐藏重复语义；不通过全局隐藏 SVG 处理。
- D07/D08 保留并验证：主题存储、系统跟随、减少动效、强制颜色、尺寸和背景。D09 只在真实浮层溢出被证明后处理。

参照 [Carbon 颜色职责](https://www.carbondesignsystem.com/building-blocks/foundations/color/guidelines)、[JetBrains 字体](https://plugins.jetbrains.com/docs/intellij/typography.html)与[图标规范](https://plugins.jetbrains.com/docs/intellij/icons.html)。达标目标来自 [WCAG 普通文字](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)和[非文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)，按实际控件判断；装饰线与禁用态不能机械套用。

## 每个动作、图标和组件的统一规则

| 类别 | 统一规则 | 必要性及保留边界 |
| --- | --- | --- |
| 主操作 | 当前步骤只有一个清晰主要动作；保存/执行与停止、关闭、取消分开 | 提高反复操作时的辨认速度；不把所有工具条按钮都涂成主色 |
| 危险操作 | 名称明确对象和范围；沿用已有二次核对、单次批准及忙碌保护 | 防止误读后操作；不新增任意确认，不省略既有确认 |
| 高频/低频动作 | 刷新、执行、保存、连接直接可见；管理性清除、批量显隐可进入有名菜单 | N16/N17/W07 减少并列辨认成本；活动事务和不确定状态必须可见 |
| 禁用与加载 | 禁用原因可键盘查看；加载/重连与失败/断开分开表达 | N03/W01 修复“未知被写成确定结论”；不自动发起远端重试 |
| 图标 | 返回、关闭、展开、连接、查找、复制、刷新、保存保持现有语义；类型图标按注册表 | N05/D06 提高跨模块一致性；已合理的图标保留，不为风格更换库 |
| 文案 | 写范围、动作和用户结果；配置完成、连接在线、未保存、待读取分别表述 | N02/N07/N13/N14/W04/W09/W12 消除混淆；安全术语保留必要精度 |
| 键盘 | 普通表单保留 Tab；树和数据网格单入口后用方向键；搜索受当前区域约束 | W02/W03 避免大量停靠；遵循[APG树](https://www.w3.org/WAI/ARIA/apg/patterns/treeview/)和[网格](https://www.w3.org/WAI/ARIA/apg/patterns/grid/) |
| 编辑器 | 查看和编辑复用已有 CodeMirror 能力；格式化是用户动作 | W06 提供行号、撤销、搜索；不得自动改值、改编码、改TTL或扩大写能力 |
| 变更审查 | 展示将批准的完整信息，支持定位多个变更，超限明确降级 | N01/W05 降低遗漏；显示算法不能改变最终确认参数或写入内容 |
| 搜索结果强调 | 对已有加载内容进行文本匹配，使用安全文本节点 | W08 提高排查效率；不得通过 HTML 注入或扩大日志读取范围 |

这些规则作用于现有功能，没有为每个合理按钮制造独立改动。逐个模块及组件的保留理由、图标与交互覆盖见附录。

### 实施复审与必要性

- N09：专业工作区前台运行、连续缩窄并恢复主窗口时，实测后台三栏由约 178.83/299.58/319.59 px 漂移为 178.20/571.80/48 px；恢复到 1440 px 后仍为 300/1090/48 px。保存记录的 `detailCollapsed` 仍为 false，却已保存 31.315/63.675/5.01 的临时比例，返回详情后入口不可见。范围与连接没有改变。后续复验还发现无保存记录时导航恢复为 176/240 px，证明恢复时也必须等面板库按新尺寸更新约束，不能拿旧窗口约束校验新比例。先记录证据再修保存/恢复边界，区分程序性压缩与用户操作，保留用户主动拖动及显式折叠。指标回归等待原入口、比较原工作区，禁止测试自行展开以掩盖问题。
