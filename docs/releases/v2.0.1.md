# 2.0.1 · Windows 云仓库版

已知问题：本版在线更新使用非静默安装向导，但启动时隐藏了窗口，可能出现客户端退出后没有重新打开的现象。该问题已在 [2.0.2](v2.0.2.md) 修复；旧更新器需先完成修复版安装，后续升级才采用静默安装流程。

本版通过现有 HTTPS 云配置仓库分发 Windows x64 安装包，提供 Agent 自行连接及软件在线更新能力，并用于验证已具备更新功能的 2.0.0 客户端升级到 2.0.1。本次不创建 GitHub Release，不变更 GitHub 的 2.0.0 下载入口或 Latest。macOS 保留源码构建，暂不支持桌面在线安装。

## 主要变化

- Agent 可使用 `connect_environment` 或 `connect_plugin` 连接明确指定的项目、环境与插件；凭据由本机管理，首次 SSH 指纹确认和缺失凭据仍须人工处理。
- “设置 → 关于”新增软件更新入口，从已关联并解锁的云仓库选择来源，启动时及每 15 分钟检查新版本；支持手动下载、后台进度、取消下载及确认重启安装。
- 现有云服务独立分发版本清单和安装包，客户端通过 HTTPS 获取，不携带配置仓库的密码或 token，并校验产品、版本、平台、架构、文件大小和 SHA-512。
- 安装前再次校验下载文件，检查未完成任务与未保存内容，停止接收新操作并关闭连接后启动安装。保留项目、已保存凭据与云仓库关联，继续执行原有 SSH 指纹验证和 Agent 操作审批。

## 体验 2.0.0 → 2.0.1 在线升级

前提是当前 Windows x64 的 2.0.0 客户端已经手动安装了含“软件更新”入口的构建，并已关联提供 2.0.1 的 HTTPS 云仓库。原 GitHub 2.0.0 安装包不含此入口，首次使用须先手动安装支持更新的客户端。发布者上传新版本不会自动升级正在运行的客户端。

1. 保持当前 2.0.0 客户端运行，进入“设置 → 关于 → 软件更新”。
2. 选择已有的 HTTPS 云仓库作为更新来源，点击“检查更新”，确认发现的版本是 **2.0.1**。
3. 点击“下载更新”，观察进度；下载期间可以返回工作台继续使用，完成后不会自动安装。
4. 保存编辑内容，结束 SQL 事务、文件传输与其他运维任务，再点击“重启并更新”，确认更新到 2.0.1。仍有活动任务时客户端会阻止安装，处理后可重试。
5. 客户端退出后使用 Windows NSIS 安装向导，按提示完成安装并重新打开客户端。本版可能隐藏向导并等待输入，请参照上述已知问题；当前不是全程静默安装。
6. 在“关于”确认版本为 **2.0.1**，检查原有项目和云仓库关联仍在。重新打开 Agent 客户端，重新获取环境上下文并连接资源。

升级沿用原安装位置和 `AIOpsTool` 数据目录，不通过卸载删除数据。操作前建议备份 `%LOCALAPPDATA%\AIOpsTool`；自定义数据目录用户备份对应目录。安装包尚未进行 Windows 发布者数字签名，可能出现未知发布者提示，请遵守所在组织的安装要求。

## 发布文件

Windows x64 的云仓库目录为 `updates/win32/x64/`，包含 `latest.yml`、`RunbookBridge-2.0.1-win32-x64.exe` 及可选的同名 `.blockmap`。安装包须先上传并校验，版本清单最后原子替换；保留旧包以便已开始下载的客户端完成下载。具体准备与部署命令见[软件在线升级](../software-updates.md)。
