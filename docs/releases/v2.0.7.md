# 2.0.7 · 工作区直接关闭

## 使用变化

- 服务器、MySQL、Redis 工作区的关闭按钮与工作区列表中的关闭入口均直接关闭，不再要求二次确认。
- 关闭会丢弃当前工作区的未保存草稿、查询与浏览状态，结束人工终端，并释放 SQL 会话、回滚未提交事务；插件连接保持，其他工作区不受影响。
- 保存或文件传输仍在进行时，先等待任务结束。Redis 写入结果尚未确定时，先核实结果再关闭；MySQL 会话释放失败时保留工作区并显示错误。
- 「返回详情」继续保留工作区。单个文件、SQL / Key 标签、数据写入和应用退出的确认规则保持原有行为。

## 分发

本次通过现有 HTTPS 云仓库发布 Mac arm64 和 Mac x64 的 DMG、ZIP 与独立更新清单，Windows x64 保留 2.0.6。保留旧版本文件，不创建 GitHub Release。

已安装 2.0.6 的 Mac 用户在「设置 → 关于 → 软件更新」选择已连接的海外仓库，检查更新并下载 2.0.7。校验完成后打开 DMG，退出旧应用，再拖入 Applications 覆盖安装。

沿用手动安装通道的临时签名，未进行 Apple 公证，不自动替换正在运行的应用。

- Mac arm64 和 x64 的更新清单已于 **2026-10-13 23:59（北京时间）**启用，均指向 2.0.7。已在原 2.0.6 客户端验证海外仓库显示「发现新版本 2.0.6 → 2.0.7」。
- 安装包对应提交 `19968da357645be7077b83ee17effea4d7d6ab53`，构建目录无未提交修改，双架构内容标识为 `fac854177ad0ce97f7f6dc8c250250de12fe2a3193d70bbca95dc1ec81f26f2b`。
- 干净提交通过语法、类型检查及单元测试：2074 项通过，2 项跳过。界面验证覆盖服务器直接关闭、MySQL 草稿及会话释放失败、Redis 草稿清理、后台工作区关闭，以及基础界面。
- 两个实际安装包均通过结构、42 项 MCP 工具、120 项 preload API 的包内界面及代码签名检查。

验证中发现两处旧测试对运行环境的假设：上传测试误将 macOS `/private` 临时路径当作敏感字段，在普通工作目录重新全量运行后通过；旧终端恢复脚本仍假设全局搜索快捷键不会打开弹层，本次使用独立工作区管理场景验证后台关闭。新场景按编辑器实际按需挂载行为，在恢复前台后核对 SQL 草稿。
