# 上传续传与速度优化（2026-09-16）

## 已实现范围

复用现有 `ssh2`，不增加生产依赖。桌面上传采用有界并发分块写入；在应用及所属 Renderer 保持运行时支持中断后手动续传。MCP 上传仍走原执行入口，不增加恢复工具或权限。

使用步骤：上传中断后，重新连接同一服务器，打开原工作区，在文件传输中点击「继续上传」，核对路径、大小、已传进度后确认。存在同名目标时仍需明确勾选覆盖。

- 每次中断保留 30 分钟，最多手动续传 3 次。
- 每个文件最多 500 MiB，最多 2 个同时上传。
- 返回详情保留任务；关闭应用或销毁所属窗口后不恢复。
- 连接配置、配置修订、主机指纹或目标目录变化时拒绝续传。
- 不支持恢复任意历史临时文件、跨进程恢复、目录递归或文件秒传。

## 写入与恢复

`src/server-upload-transfer.mjs` 每批最多读取 1 MiB，发出最多 32 个 32 KiB 的 SSH2 写入调用。只有整批回执全部成功，才在主进程内存保存连续偏移及该前缀 SHA-256。SSH2 可能按服务端限制进一步拆包。

临时文件大小不能充当恢复偏移：后续块先到达时，文件中间可能仍有空洞。恢复时从已确认的连续偏移重写尾部，尾部最多重传一批；不按临时文件大小跳过内容。

恢复前重新读取并核对完整本地文件哈希，使用固定文件句柄读取内容，再以有界并发方式读取服务器已确认前缀并校验哈希。临时文件必须是当前任务创建的随机路径、普通文件、路径未改向且大小合理。完成后检查本地身份、实际读取内容哈希、远端大小、目标前置条件和目录映射，再通过既有重命名提交。仍保持原覆盖权限；不支持覆盖的服务端不会先删除旧目标。

重命名成功但回执丢失时，恢复流程先核对临时文件是否消失及目标完整内容；匹配后记录完成，不重复写入或再次覆盖。校验不能证明远端磁盘持久性，也不能阻止外部程序在最终检查之后再次修改文件。

主动取消会有界尝试删除任务自己的临时文件；断线、状态不确定或内容被外部修改时保留文件，避免误删。取消中断任务、过期或退出应用会丢弃恢复记录，服务器可能遗留 `.part-*` 文件，本轮不自动扫描清理历史文件。

## 授权与资源边界

- 新增桌面 IPC `serverWorkspacePrepareUploadResume(scope + jobId)`，仅接收原任务标识。
- 新签发最多五分钟有效、一次性消费的确认，绑定原文件参数、前置条件、当前检查点及当前连接代次。
- Renderer 不能传入恢复偏移、临时路径、哈希、本地源路径或其他目标。
- 旧操作退出前不能恢复；旧回调不能推进新任务状态。任务元数据有数量上限，保留期间不持有打开的文件或 SFTP 句柄。
- 取消、配置删除及窗口销毁仍使任务失效；审计只记录任务元数据，不记录内容、凭据、哈希或临时路径。
- 桌面 preload API 共 78 个；MCP 仍为 36 个。

## 可重现测试与性能证据

```powershell
node --test test/server-upload-resume-runtime.test.mjs test/server-workspace-files.test.mjs
node --test test/server-workspace-upload-throughput-probe.test.mjs test/server-workspace-upload-resume-probe.test.mjs
corepack pnpm run test:ui:server-workspace
```

测试使用真实 SSH2 客户端及回环地址的 SFTP 服务端、临时密钥、固定主机密钥校验和随机文件，不连接真实基础设施。覆盖空文件、32 MiB 文件在 25 MiB 检查点恢复、连续两次断线、未回执尾部、同长度且保留时间戳的源文件变化、临时前缀篡改、链接及超大文件拒绝、目标变化、取消清理、覆盖保留权限、不支持覆盖、提交回执丢失和命令通道并存。桌面任务集成测试覆盖真实断线事件→新确认→原任务完成；另覆盖跨窗口/作用域、配置变化、过期、重复确认及尝试次数限制。

4,194,317 字节文件、写入回执延迟 80 ms 的本机夹具测量：旧正式上传入口约 4.62 秒，新入口约 0.85 秒，约 5.4 倍。计时包含执行阶段的本地校验与最终提交，不包含用户选文件后的后台预检，也不是实际公网 RTT 模拟。低延迟结果有波动，其中一次旧入口 72 ms、新入口 82 ms，另一次 163 ms 对 107 ms；不声称所有网络都会更快。

恢复校验需要额外下载已确认前缀；接近完成的大文件恢复可能花较多时间。未验证真实公网弱网、大文件长期运行、多种生产 SFTP 服务端及磁盘故障，不承诺零回归或固定提速倍数。建议先用非关键文件体验，再决定是否扩展到更大并发或其他传输策略。
