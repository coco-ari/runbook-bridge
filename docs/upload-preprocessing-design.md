# 上传后台预处理：风险评估与实现

## 结论与范围

沿用现有 ssh2、文件预检与上传执行能力，采用「清单先显示、后台检查、完成后确认」流程。风险评估为中等，主要来自异步任务生命周期；不需要新增生产依赖。本文列出的控制措施和回归用于降低风险，不能作为所有服务器环境均无问题的保证。

## 兼容性与风险

| 现有能力 | 可能的冲突 | 控制方式 |
| --- | --- | --- |
| 一次性上传确认 | 清单已显示但检查未完成时误上传 | reviewId 与 preparationId 分离；只有检查成功才生成原有一次性凭证 |
| 移除已检查文件 | 重读所有文件，或错误复用已过期/已消费凭证 | 只复用成功且有效的严格子集；原子替换清单与凭证，保留原有效期和每个文件的前置条件 |
| 同名覆盖 | 检查状态变化后沿用旧勾选 | 检查期间禁止上传及覆盖勾选，每次重查清除覆盖选择 |
| 固定上传目录 | 链接改向或后台结果改变目标 | 绑定原逻辑路径与实际目录，重试、确认及提交前复核 |
| 取消、关闭、重新选择 | 迟到结果恢复旧任务或凭证 | AbortSignal 贯穿哈希及 SFTP，任务身份与 Renderer 选择代次双重校验 |
| 连接与配置切换 | 旧连接的检查结果被新连接使用 | 继续绑定 owner、作用域、配置 revision、SSH generation；失效任务不能签发凭证 |
| 已有终端和文件浏览 | 取消检查导致 SSH 断连 | 只结束预处理持有的 SFTP 通道；在本地真实 SSH 测试中验证取消后终端回显及文件预览正常 |
| 上传超时、速度与提交 | 预处理改动污染正在执行的任务 | 使用独立检查任务及错误提示，上传执行继续通过原有 confirmUpload 与 runJob |
| Agent/MCP | 桌面预处理选项被传入 Agent 工具 | 新增接口仅限可信桌面主框架；内部快照及取消选项不进入 MCP 参数 |

## 实现流程

1. 原生文件选择完成后，仅读取本地元数据，返回路径、大小和 checking 状态。
2. 后台使用一个 SFTP 只读会话顺序检查实际目录与全部目标文件，保留前置状态。
3. 释放该会话，再流式计算本地文件哈希并更新字节进度，避免本地大文件读取期间占用闲置 SFTP 会话。
4. 使用第二个只读会话复核目录映射，重新检查窗口、作用域和连接绑定，随后生成原有上传凭证。
5. 用户明确确认后才进入上传队列。执行时仍核对源文件哈希、目标状态，并以临时文件完成提交。

当前不增加远端检查并发。批次为 1、5、20 个文件时，正常检查均使用两个 SFTP 会话，元数据请求数量仍随文件数量增加。更少的通道不能消除网络请求与完整文件哈希本身的成本。

## 生命周期和资源上限

- 每个窗口最多保留一个预处理任务，每批 1–20 个普通文件，单文件上限仍为 500 MiB。
- 后台检查总时限 10 分钟；每个 SFTP 只读会话沿用 120 秒上限。
- 检查完成后才开始计算 5 分钟确认有效期；查询状态和移除文件均不会续期。移除成功后的 reviewId 和 preparationId 都替换，旧结果不能覆盖新列表或继续确认。
- 检查期间允许复制路径、取消和关闭弹窗；移除文件和重新检查在本次检查结束后进行。
- 重试从原生选择保存的路径建立新任务；Renderer 不能新增本地路径或更换目标目录。
- 取消检查不会自动上传、重试传输或删除远端文件；检查阶段只有只读远端操作。

## 桌面接口

- serverWorkspacePickUpload：返回 ServerUploadReview 或 null。
- serverWorkspaceReadUploadReview：凭作用域及 reviewId 查询状态与进度。
- serverWorkspaceCancelUploadReview：取消检查并撤销未消费凭证。
- serverWorkspaceReviseUpload：只接受 reviewId 和原文件名子集。成功且未过期时，严格子集直接返回 ready 的新清单及凭证；原文件集合表示主动重查，失败或过期后移除也返回 checking 的新后台任务；空集合返回 null。
- serverWorkspaceConfirmUpload：继续仅接受 preparationId 与 overwrite。
- 桌面 preload API 数量为 78；现有 36 个 MCP 工具的参数与行为契约不变。

文件清单包含本地路径供人工展示与复制；不包含哈希和状态前置条件。检查任务不写入磁盘，不记录本地文件内容。
