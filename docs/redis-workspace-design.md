# Redis 工作区

Redis 插件连接完成后，在插件详情的连接操作旁点击「打开 Redis 工作区」。提供固定 Logical DB、已登记 Key 范围内的浏览，以及桌面人工 String/JSON 新增编辑和单 Key 删除；不提供切库、任意命令控制台或通配符批量删除。

## 浏览与查看

- 树上方展示固定 DB、当前 Key 范围、新增 Key 与刷新、视图切换、更多工具；搜索框单独一行。窄侧栏允许操作区换行，保持文字按钮可见。只有多个已登记范围时才显示范围切换菜单，单个范围直接展示。配置为 `*` 时显示「全部 Key（*）」，没有范围时不会自动扩大授权。
- 搜索区分大小写，普通关键词按包含匹配；支持 `*` 匹配任意长度字符、`?` 匹配单个 Unicode 字符，反斜杠转义通配符。未包含未转义的 `*` 时自动按包含匹配，例如 `user` 与 `*user*` 都能找到 `cache:user:1`，`user:*` 只匹配此前缀。`[]` 按字面字符处理，不解释为字符集合。勾选「精确匹配」后直接定位完整 Key，仍检查当前范围。
- 搜索框聚焦时显示最近搜索，输入仅筛选本地历史，不自动访问 Redis；可用上下方向键和 Enter，或点击候选项直接复用，并恢复当时的精确/模糊模式。当前工作区最多保留 20 条记录，按项目、环境、插件及已登记范围隔离，可清空当前范围记录。历史仅驻留内存，返回详情后保留，明确关闭工作区或配置身份失效后清除。
- 右键目录选择「搜索此目录下的 Key」，或选中目录后从更多工具选择「搜索所选目录」，自动填入该目录前缀并开始模糊搜索。目录名中的 `*`、`?` 和反斜杠会先转义，仍限定在当前已登记范围内。
- Enter 或搜索按钮提交一次后自动跨越空批次，结果逐步显示，累计新增约 500 个不同 Key 后暂停；匹配不足一页时继续到扫描完成。点击「继续搜索」从当前位置加载下一页。只有游标结束且结果全部保留才显示「搜索完成」。
- 搜索过程中可点击「停止搜索」；当前在途批次返回后保留结果和最新游标，不再发起下一批。输入新词、切换匹配方式或返回详情也会停止自动续扫，但不会自动提交新搜索。重新提交、刷新或切换 Key 范围会从头开始，旧查询的迟到结果不能进入新查询。
- Key 默认按冒号 `:` 分层显示为目录树，支持目录展开/折叠和完整名称列表切换。「更多工具」菜单提供定位当前 Key、全部展开/折叠和收起 Key 列表。叶子显示完整 Key，保留末尾冒号，悬停和底部路径栏也显示完整名称；同名 Key 和目录分别保留。目录数字只统计已加载的 Key。
- 搜索结果保留层级并展开匹配路径，继续扫描会合并到原目录并保留展开状态；「定位当前 Key」可展开路径并滚动到已加载的当前 Key。方向键、Home、End 导航目录，Enter 打开 Key，Ctrl / Command + Enter 固定标签。异常深层 Key 的前 12 层显示目录，叶子仍显示完整 Key。
- SCAN 自动按批次继续，只显示已加载数量，不显示推算的完成百分比。空批次不表示完成；返回游标结束才表示本轮完成。外部数据可能变化，不保证静态快照。列表不逐项查询类型或 TTL。
- 单击 Key 使用临时预览标签，双击固定，最多 8 个标签。每个标签独立保留显示方式和滚动位置。
- String 自动识别 JSON，支持文本、JSON 格式化及十六进制；Hash 显示字段和值并支持精确字段读取；List 显示索引和值；Set 显示成员；ZSet 显示从零开始的排名、成员和分数。其他类型只显示类型、TTL 等可用摘要。
- TTL 是读取时的采样值，区分剩余时间、不过期和不存在，不自动轮询。刷新 Key 会重新读取元数据和内容。
- 内容区顶部将类型标签、Key 名称与「复制 Key」图标集中排列；大小或成员数、TTL、读取时间位于下一行，刷新图标紧邻采样时间。文本、JSON、十六进制使用分段切换，旁边的「复制内容」复制当前显示内容；截断时明确显示「复制已加载部分」。数据以纯文本渲染，JSON 不执行代码或 HTML，也不会打开内容中的链接。
- Value 参考 ARDM 的结构化显示：JSON 语法高亮、逐层折叠、全部折叠/展开、默认自动换行，并支持在已加载内容内查找。内容获得焦点时 Ctrl / Command + F 查找 Value，其他位置仍聚焦 Key 搜索。查看器只读，切换显示方式、折叠、查找及复制不会访问 Redis。
- JSON 格式化仅调整字符串外空白，保留大整数、小数表示、重复字段及原始转义；复制包含折叠部分。5 MiB 以内的 String 自动完整打开，无需续读；5～20 MiB 先预览，一次「完整打开」即可查看全部并编辑，也可直接点击「编辑」准备完整草稿。超过 20 MiB 采用分段浏览，只保留当前段，并提供完整原始内容导出。预览片段不补齐数据，完整但非法的 JSON 保持原文显示。
- 查看与编辑复用 CodeMirror 的高亮、折叠和视口渲染；切换时尽量恢复滚动、查找和选区，仅在文档布局相同时恢复折叠范围。JSON 识别、格式化、校验及文本十六进制转换使用本地 Worker，输入校验防抖 180 ms。格式化超过 40 MiB 或节点片段数量过多时回退原文，缩进最多 32 层；大于 1 MiB 默认不自动换行。文本按需生成十六进制，避免常驻双份数据。
- 左侧栏可拖动调整或折叠，Ctrl / Command + F 聚焦 Key 搜索；标签支持方向键、Home、End 和 Delete。

## 会话与限制

「返回详情」隐藏工作区并保留数据，隐藏期间不发起后续读取；点击「返回 Redis 工作区」继续浏览。「关闭工作区」直接清除草稿、数据和读取通道，不再二次确认，插件主连接保持。切换插件保留工作区，最多保留 4 个 Redis 工作区。手动断开或网络掉线后保留工作区、Key 标签、当前标签、搜索条件与历史，以及编辑草稿，不再返回详情或清空浏览现场。离线停止读取和扫描，仍可修改已有草稿；工作区内可重新连接，连接失败不会丢失内容。重连仅恢复操作能力，不自动搜索、读取或写入。旧搜索和 Key 内容标记为断线前的数据，扫描与集合分页游标失效；手动重新搜索或刷新 Key 后才可继续读取、编辑或删除。草稿在用户再次点击保存时自动读取新基准；原值未变即可继续，有内容冲突时才提示对比。旧删除确认与尚未提交的准备结果失效；已经发出的写入自动查询结果，不自动重试写入。配置修订、删除所属资源和窗口销毁会失效旧会话，迟到请求不能恢复它。

桌面默认单次 IPC 返回最多 100 个 Key，集合每批最多 50 条，均受插件 `maxKeys` 限制；列表最多保留 5,000 个 Key。集合及大值分段仍使用 `maxValueBytes`（默认 64 KiB）；超大 Hash 单字段不读取正文。桌面 String 完整查看和编辑使用独立的 5 MiB 自动打开、20 MiB 手动打开与编辑预算，由 `src/redis-desktop-limits.json` 同时提供给前后端，不更改 Agent/MCP 的 `maxValueBytes` 策略。UTF-8 分段保留字符边界；二进制 Value 可查看十六进制和导出，不支持文本编辑。

完整 String 使用一次有界 GETRANGE 取得内容快照，前后检查长度与类型，并返回原始字节 SHA-256 指纹；进入编辑时对照该指纹，等长替换也会要求刷新。超过 20 MiB 的分段浏览不拼接为可编辑文档；游标单次消费，绑定窗口、作用域、Key、范围、配置与连接，长度变化时要求刷新，段与段之间不承诺静态快照。切换 Key、隐藏或断线会忽略迟到的读取结果；重连后仍须用户刷新。

一次前端搜索最多自动续查 30 秒或 1,000 次 IPC，批次间让出至少 20 ms；在途请求仍受插件超时约束。预算达到后保留结果与游标，明确提示可以继续，不能解释成查无结果。隐藏期间停止续查，返回工作区后由用户选择继续。

有关键词时，后端每次 IPC 最多合并 8 条 SCAN，批次间检查 100 ms 工作预算；单条命令仍使用插件约束后的 COUNT，整次请求仍共用原有超时。SCAN 的 MATCH 始终使用已登记范围，再以搜索模式进一步过滤，用户输入不能扩大授权范围。搜索匹配采用有界迭代算法，不将用户输入转换为回溯正则。

Redis 的 COUNT 是提示而非严格条数保证，扫描超额余项在主进程暂存，游标有效期五分钟。主进程集合余项预算 4 MiB；Renderer 浏览数据按字符串 UTF-16 驻留大小估算，预算 96 MiB，优先释放非活动标签浏览内容；独立编辑草稿不因浏览缓存淘汰而丢失。后端待提交值合计最多 64 MiB。以上是各类保留数据预算，不代表进程 RSS 上限，编辑历史、格式化结果和协议处理仍有额外内存。

每插件最多一个桌面浏览或导出请求；普通读取共用插件超时。独立 RESP2 通道复用主连接路由与相同认证、DB、TLS 参数。默认回复仍限制 1 MiB；仅合法非负范围、最多 20 MiB 的桌面 GETRANGE 按实际请求长度放宽回复预算，并保留 64 字节协议余量。解码器在正文声明时检查上限，一次分配正文缓冲区，避免逐片重复复制；数组节点和深度上限不变。超限、超时或格式错误关闭独立通道，不关闭插件主连接。

## 桌面接口与安全边界

`redisWorkspaceScan`、`redisWorkspaceInspect`、`redisWorkspaceRead`、`redisWorkspaceRelease`、`redisWorkspaceExport` 五个 preload API 沿用 `IpcResult`。请求携带项目、环境、插件及 `patternId`，拒绝凭据、地址、任意命令、切库和本地路径参数。

`redisWorkspaceRead` 新增可选 `full: boolean`，不能与 cursor 或 field 混用。完整值返回可选 `value.digest`；有效文本的 hex 可为空，界面按需生成。大值当前段的 `offsetBytes` 是原始字节偏移，`shownBytes` 是当前段字节数，`bytes` 为总大小；即使最后一段也标记 truncated，避免把末段误认为完整值。集合契约不变。

IPC 校验可信主窗口及主 frame；服务层检查完整作用域、当前连接、配置状态和内置操作授权，操作前后均复核会话。窗口及工作区释放凭证还覆盖等待审计时的竞态，旧请求不能在释放后重新建立读取通道。读取共用既有用户操作审计；开始审计失败时不访问 Redis，完成审计失败返回 `auditWarning`。审计不保存 Key、Value、字段、搜索词或服务端错误正文。

上述接口仅供桌面人工操作，不增加 MCP 工具、不扩大 Agent Redis 能力、不修改 workspace YAML 或凭据模型。浏览与草稿只驻留内存；复制及导出都由用户明确点击。导出路径由主进程保存对话框选择，Renderer 不能指定；最多 512 MiB，每次读取 256 KiB，整体最多五分钟且单次命令受插件超时约束。在独立连接 WATCH 下分段写入同目录临时文件，最终以只读 MULTI/PTTL/EXEC 校验期间没有修改（包括等长替换），复核窗口、连接、配置与目标文件后才替换目标。取消、断线、冲突或失败清理临时文件并保留原目标。

## 新增、修改和删除

从 JSON 查看进入编辑保留格式化排版、滚动位置、搜索及折叠状态。若正文未改动，保存使用原始文本，避免仅查看、切换编辑或调整有效期就重写空白；用户实际修改后保存草稿正文。后台校验期间按保存快捷键会等待本次校验完成，继续输入则取消待保存动作，避免提交过期草稿。

左侧顶部及空状态提供「新增 Key」，详情提供「编辑」「删除 Key」。新增在固定标签中填写 Key、文本/JSON 和有效期；默认永久保存，不覆盖同名 Key。编辑在原内容区完成，Key 不可改；默认保留原 TTL，不重新计时。有效 UTF-8 文本在 20 MiB 内允许编辑；二进制和超过上限的值给出明确原因。加载时点击编辑可直接进入完整读取准备，完成后自动显示草稿。JSON 后台校验显示错误行列且不改变原文或大整数，Ctrl / Command + S 保存。

保存一次点击即可完成。编辑标签自动固定并标记未保存；关闭、取消编辑、刷新当前内容或切换范围时统一保护草稿。断线、过期及冲突保留输入；再次点击保存时自动读取有效基准，服务器原值未变就继续保存，内容变化才展示服务器值与草稿供用户核对。回复丢失或结果未知时自动查询本次计划（最多 3 次），已成功则结束编辑，已失败则保留草稿并提示原因；确定为未知的终态会自动读取当前数据供核实，查询失败或仍在执行时只保留一个「重新确认结果」入口。查询与读取均不会重发写入，也不会仅凭当前值相同就声称此前操作成功。

String、Hash、List、Set、ZSet 均支持单 Key 删除。确认框显示完整名称、类型及 DB；有本地草稿时在同一框说明丢弃。标签关闭、键盘 Delete 和目录操作不会删除服务端数据。

桌面新增 `redisEditOpen/Prepare/Commit/Status/Release` 五个 API。Open 接收固定作用域、patternId、完整 Key 和 create/update/delete，以及 update 模式可选的 expectedDigest（64 位十六进制 SHA-256）；Prepare 接收 editId、原文 value、text/json 格式、过期方式 keep/persistent/relative（毫秒）；删除不接受新值。Commit/Status 只接受 editId 与 planId。所有接口拒绝任意命令、凭据、地址和切库参数。

独立有界 RESP2 写入连接绑定当前主连接代次，WATCH 从读取编辑基准或打开删除确认时开始；MULTI/EXEC 单次消费精确计划，SET NX 防新增覆盖、XX 防已过期 Key 重建，有有效期的 Key 使用 KEEPTTL 保留过期时间，永不过期的 Key 不发送此选项（WATCH 仍保护过期设置），UNLINK 删除单 Key。写入通道收齐完整 RESP 回复后区分服务器拒绝与连接中断；单条写命令的明确错误返回失败和脱敏原因，畸形或不完整的提交回复仍为未知，避免误报失败后重复写入。并发修改、过期和驱逐继续受到事务冲突保护。编辑会话 30 分钟，保存计划 2 分钟，后端最多 24 个编辑会话。审计只记录范围、操作和结果，不记录 Key、Value 或原始服务端错误。Agent/MCP 继续只读。

最低支持 Redis 6.0.9（含 WATCH 对过期的保护）；建议使用受维护的 Redis 版本。参考官方 [SET](https://redis.io/docs/latest/commands/set/)、[事务](https://redis.io/docs/latest/develop/using-commands/transactions/) 和 [UNLINK](https://redis.io/docs/latest/commands/unlink/) 文档。

验证：`node --test test/redis-data-editing.test.mjs test/redis-workspace.test.mjs`、`corepack pnpm run test:ui:redis`。授权服务器隔离验证使用 `node scripts/database-write-live-probe.mjs`，必须通过环境变量 `RUNBOOK_TEST_HOST`、`RUNBOOK_TEST_PASSWORD`（可选 `RUNBOOK_TEST_USER`）显式提供授权连接，并已在本机 known_hosts 信任主机密钥。脚本复用已安装 MySQL 8.4 镜像及 Redis 可执行文件启动临时回环实例，通过 SSH 隧道验证并清理实例，不访问业务数据，不保存凭据。
