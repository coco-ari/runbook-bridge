# 云配置仓库

工作台左侧将本地项目和云项目合并在同一个列表，不显示仓库分组标题或名称左侧的云图标，已下载项目沿用统一的拖动排序。每行右侧只保留一个状态位：平时显示连接状态，云端有更新时显示主题色下载标记，本地有修改时显示警告色编辑标记，尚未下载时显示灰色下载标记。云仓库检测失败在悬停提示和云配置页面显示，不覆盖项目连接状态；未连接仍显示灰色圆圈，连接错误仍显示红色。连接中、部分可用、阻塞、错误和隔离状态优先显示；悬停或键盘聚焦项目可查看连接状态、所属仓库和云同步状态。项目详情的更新、上传按钮旁显示云仓库名称或“本地项目”。关联仓库后自动列出其中的项目；首次打开云项目时下载配置，不需要导入向导，也不会自动连接服务器。

项目详情提供“更新”“上传”。配置 → 云配置沿用工作台的主题、按钮和卡片样式，仓库中的每个项目以紧凑卡片展示，提供显示开关和“…”菜单，底部同一排显示同步状态、单个更新和单个上传，不重复显示仓库名称。“…”提供版本记录、删除云端项目。工具栏提供搜索、全部/已显示/已隐藏/有更新/已删除筛选、全部显示、全部隐藏、检测更新和更新整个仓库，没有整库上传。隐藏仅影响本机工作台列表，保留已下载配置；全部显示/隐藏作用于当前仓库的所有活动项目，不受搜索筛选影响。仓库设置可以修改本机显示名称，不改变仓库标识或其他设备上的名称。

可关联最多 20 个仓库，每个仓库独立保存链接、解锁凭据、项目关联和显示设置。旧版单仓库记录会自动迁移。解除绑定会清除该仓库的会话和记住的凭据，已下载项目保留到本地仓库，不删除云端内容。本机加密保留不含凭据的项目 ID 关联；重新验证同一仓库后复用原关联，不按名称合并项目，也不重复下载成新项目。本机备份在解除所有仓库后仍可恢复。

默认每 15 分钟检测一次，可在仓库设置中选择 5、15、30、60 分钟或关闭；该间隔适用于本机所有仓库。应用打开时执行检测，关闭应用后不运行。定时和手动检测都只读取云端、刷新目录与图标，不覆盖项目、不自动上传、不弹出更新确认。检测失败保留上次成功读取的项目。未记住密码的仓库重启后需解锁。

检测最多并行读取两个仓库，同一窗口对同一仓库的重复检测会合并。网络等待不占用配置写入队列，因此慢仓库不阻塞其他仓库操作。关闭窗口、重新关联或解除绑定会取消相关检测，迟到的旧响应不会覆盖刚上传的新状态。

“外观主题”提供浅色、深色和跟随系统，设置立即生效并保存在本机。“返回工作台”保留原项目选择及已打开的工作区；写入及确认期间暂时禁止离开云配置页面。

## 部署

服务独立于桌面应用，使用 Node.js 24 的 `node:sqlite` 与标准加密、HTTP API，不需要额外生产依赖。当前 Node.js 24 的 SQLite API 可能输出实验性提示。Docker Compose 同时启动云服务和负责 HTTPS 的 Caddy；仅 HTTPS 代理对外暴露端口。

准备一个指向部署机器的域名，开放 80、443 端口，并安装 Docker Compose。将至少 32 个字符的随机管理员令牌保存到代码仓库外的文件，例如用以下命令创建（文件路径按实际环境调整）：

```sh
umask 077
node -e "require('node:fs').writeFileSync('/srv/runbook-cloud-admin-token',require('node:crypto').randomBytes(32).toString('base64url'),{mode:0o600})"
chown 1000:1000 /srv/runbook-cloud-admin-token
export CLOUD_DOMAIN=config.example.com
export CLOUD_ADMIN_TOKEN_FILE=/srv/runbook-cloud-admin-token
docker compose -f services/cloud-config/compose.yaml up -d --build
```

容器以 UID 1000 的 `node` 用户运行。Linux 下文件型 Compose secret 保留源文件权限，上述 `chown` 让容器可以读取权限为 `0600` 的令牌；如启用用户命名空间，请按实际 UID 映射调整。构建上下文仅允许云服务代码和两个共享模块，排除本地数据与凭据。

管理员令牌只用于创建仓库。桌面点击“创建新仓库”，填写 HTTPS 服务根地址和该令牌，保存默认生成的随机仓库密码，也可改为至少 16 个字符的自定义密码。创建后复制仓库链接；其他电脑只需链接和仓库密码，不需要管理员令牌。

持久化数据位于 `cloud-data` 卷中的 `cloud.sqlite`，Caddy 证书位于 `caddy-data` 卷。备份数据库时先停止云服务，完整备份数据卷，再启动服务；不要只复制运行中的 SQLite 主文件而遗漏 WAL。恢复时使用同一份完整数据卷。服务健康检查为内部 `GET /healthz`；日志不记录密码、访问头或配置正文。

项目管理集成在桌面云配置中，没有独立管理网站、公开注册、团队成员或权限分级。一个客户端可以关联多个仓库，知道某仓库密码的人拥有该仓库读写权限。密码更换使用新密码创建新仓库并重新上传；旧仓库停止使用或由部署管理员停止对应服务。忘记密码无法在服务端找回，可从仍保存本地配置的电脑创建新仓库。

## 可信内网 HTTP 部署

没有证书时，可使用独立的 HTTP Compose 文件，仅将服务端口绑定到内网网卡。以下为示例私网地址，需要替换为服务器实际的私网 IPv4：

```sh
export CLOUD_BIND_IP=192.168.0.10
export CLOUD_HTTP_PORT=18083
export CLOUD_ADMIN_TOKEN_FILE=/srv/runbook-cloud-admin-token
docker compose -p runbook-cloud -f services/cloud-config/compose.internal.yaml up -d --build
```

桌面创建仓库时填写 `http://内网IP:18083`，绑定时填写 `http://内网IP:18083/r/仓库标识`。HTTP 仅允许 IPv4 私网（10/8、172.16/12、192.168/16）及回环地址，公网地址与普通域名仍要求 HTTPS；不跟随重定向。客户端不需要证书或关闭证书校验。

这是用户选择的传输安全边界调整：快照仍在客户端端到端加密，原始仓库密码和数据密钥仍不发送给服务器，但管理员令牌和仓库访问凭证在 HTTP 上传输时可能被监听、复用，攻击者也可能阻断或替换响应。仅用于可信内网，不应把端口映射到公网。原有服务器 SSH 指纹验证与其他插件 TLS 校验不受影响。

## 同步内容和操作

每个项目包含环境、服务器/MySQL/Redis 插件、操作规则、Redis Key 范围、环境 Runbook、环境快捷提问，以及已保存的密码、代理密码、SSH 私钥和口令、TLS CA/客户端证书/私钥。不会上传整个应用目录；审计日志、编辑草稿、连接状态、审批、Broker 令牌、全局快捷提问开场白和界面布局均不参与同步。

“更新”始终表示云端到本地。点击后按规范化配置和凭据的 SHA-256 哈希判断：与最新版本相同则无需写入；与上次同步基线或已知云端历史版本一致则直接覆盖；无法匹配已知版本才提示确认本地修改。确认后完整替换该项目，包括删除云端不存在的插件、配置和凭据，保留本地审计。取消不覆盖。整库更新作用于当前仓库已下载的项目（包含隐藏项目），先更新无冲突项目，再集中确认有本地修改的项目；尚未下载的项目仍在首次打开或点击单个更新时下载。

每个云快照解密后计算项目哈希；最近看到的项目哈希加密缓存在本机，必要时读取云端保留的历史快照匹配。若某旧版本已被服务端清理、本机也从未记录过该哈希，则保守地按本地修改要求确认。确认有效期 5 分钟，绑定具体仓库、快照、本地配置和凭据版本，只能使用一次；确认前本地再次变化会拒绝写入。

“上传”始终表示本地到云端。点击即用该项目的本地配置完整覆盖对应云项目，不再展示上传预览或冲突选择。上传重新读取云端最新快照，只替换当前项目，保留其他云项目；条件提交遇到并发变更时最多重试 3 次，云端持续变化则提示重试。上传不支持整库操作。

项目关联使用 ID，不使用名称。新上传的云项目使用随机 UUID，原有云项目的 ID 保持兼容。首次上传本地项目后归入相应云仓库；项目详情中的“上传到其他仓库”创建具有新 ID 的云项目，原关联保留，两个仓库中的项目独立更新。在左侧打开新副本后，本机也保存为独立项目。同名或同 ID 但没有同步关联的本地项目不会被自动覆盖。

上传或下载前先持久化选定的项目 ID 关联，保存失败则不执行同步。云端写入响应丢失、配置提交后的同步基线保存失败或应用重启后，重试仍沿用该 ID；重复上传相同配置不会新增项目或项目版本。

下载前检查活动编辑和文件传输；存在活动任务时先完成或取消。覆盖会断开该项目的连接，取消该项目的 Docker 读取并清除分页快照，同时使旧 Redis 浏览游标、Agent 上下文及审批失效；其他项目的 Docker 和 Redis 会话保持可用。导入以项目为原子单位，多个项目逐项显示完成或失败。每次覆盖前将本机配置和凭据保存为系统加密备份；“本机备份”可确认恢复。未完成事务在下次启动时恢复；无法解密或恢复的项目保持隔离，不允许继续连接。

备份列表仅在打开“本机备份”时读取，每页最多加载 20 个文件，提供刷新和加载更多。无法读取的备份会单独计数提示，保留原文件，不影响云配置状态和其他备份；选择损坏备份恢复仍会拒绝操作。当前不自动清理本机备份。

项目卡片“…” → “版本记录”打开侧栏，展示时间、名称、环境/插件数量、短哈希和变更摘要，不展示凭据。每个项目独立保留最近 20 个版本；重复上传相同当前配置不新增项目版本。其他项目上传不会挤掉该项目的记录。选择“恢复为最新版本”并确认，将旧配置作为新版本发布到当前云仓库，保留原项目 ID 和其他项目。恢复动作新增记录，即使配置与某个历史版本相同。本地配置保持不变，再点击“更新”才下载。

卡片“删除云端项目”确认后仅移入当前仓库的已删除列表，保留已有本地副本。筛选“已删除”可在 30 天内查看版本并恢复项目，恢复保持原 ID。到期后不再提供恢复入口，下一次云端写入时从当前快照清理过期内容，保留只含项目 ID 和删除时间的加密删除标记（最多 10,000 条）；检测本身不写云端。服务端旧密文快照仍按原保留策略轮换，因此该期限不代表物理安全擦除。检测到其他设备删除云项目时不会删除本地文件。普通上传不能重新创建该 ID，包括恢复期限已过的项目；在回收站明确恢复后才可继续同步。超过期限时需创建新本地项目后上传。

工作台“删除项目”默认只删除本地，可勾选同时删除指定仓库的云项目。确认框展示仓库与云项目名称，并沿用输入本地项目完整名称的确认。先完成云端删除，再按原本地删除规则检查连接和删除；云端失败时本地保留，云端成功而本地失败时显示部分完成，可重试本地删除。仅删除本地后仍可重新下载云项目；隐藏用于从工作台列表移除而保留配置。

云端删除、恢复确认有效期 5 分钟，绑定窗口、仓库会话、项目、所选版本和整个仓库快照，只能用一次。提交使用条件写入；期间其他设备修改仓库则拒绝提交，刷新后重新确认。配置与凭据仍在主进程处理，确认摘要不携带凭据。

新版读取 schema 1、2、3 快照，在首次上传、删除或恢复写入时升级为含删除保护的 schema 3。schema 1 尚存的历史会迁移为项目历史；已被清理的历史和旧版已清理的删除记录无法补回。服务端 API、密钥和加密信封保持兼容，无需升级服务端；旧版客户端无法读取 schema 3，使用同一仓库的设备应全部更新客户端。全部当前配置、项目历史、已删除内容和删除标记共享单个密文快照 20 MiB 上限，超限会拒绝整次写入，不丢弃现有历史或其他项目。服务端继续保留最近 20 个整库密文快照，项目历史存在最新快照内。本机备份与当前操作系统安全存储绑定，不适合作为跨设备迁移文件。

## 加密与连接边界

客户端以随机 32 字节盐和固定 `scrypt N=131072,r=8,p=1` 派生根密钥，通过绑定仓库 ID的 `HKDF-SHA-256` 分离访问凭证和数据加密密钥。服务端持久化访问凭证的 SHA-256 摘要。原始仓库密码及加密密钥不发送到服务器。

快照整体使用 `AES-256-GCM`、随机 12 字节 nonce、16 字节认证标签；格式版本、仓库 ID、快照 ID和父版本均参与认证。项目名、连接地址、运维说明也在密文中。服务端仍能看见仓库标识、版本时间、密文大小和网络来源。强随机密码用于抵御密文泄露后的离线猜测；“限流”不能代替强密码。

下载解密在 Electron 主进程完成，凭据重新加密存入目标机器的凭据库。SSH 文件私钥上传时只读取已明确配置的普通文件（不超过 1 MiB）；导入设置 `auth.privateKeySource: vault`，私钥内容在凭据库中，由连接运行时直接使用。Server 的自定义 `target.dockerSocket` 随配置同步；原有 `privateKeyPath` 配置继续兼容，省略来源字段等同于 `file`；编辑器允许切回本机文件。

系统 VPN、SSH Agent 和硬件密钥仍依赖目标机器；未保存的密码需要在目标机器补充。仓库同步不保证网络可达。原有 SSH 主机指纹校验不变，首次信任仍需确认，指纹改变仍被拒绝。MySQL 固定数据库、Redis 范围及操作审批继续生效。

云配置不增加 MCP 工具，不向 Agent 返回凭据。桌面 IPC `v2:cloud-config` 仅允许受信任 Renderer 主框架调用；动作包括 `status/backups/bind/create/unbind/catalog/prepare/confirm/prepareRestore/check/visibility/preferences/sync/renameRepository/projectHistory/prepareProjectOperation/confirmProjectOperation`；`backups` 接受非负整数 `offset` 和 1–50 的 `limit`，仅返回本机备份摘要、当前页跳过数量及下一页位置；普通 `status` 不读取或返回备份。`sync` 按仓库和单项目执行上传或更新，只有下载允许省略项目以更新整库。管理确认和同步确认隔离，不能互换令牌或追加待写入参数。目录、检测状态及确认摘要不包含凭据值。Renderer 的 `connect-src 'none'` 保持不变，云服务请求由主进程发起并拒绝重定向。

## 云 API 与验证

服务 API 前缀为 `/api/v1/repos`：管理员认证 `POST /` 创建仓库；公开 `GET /:id/meta` 提供格式、盐和派生参数；仓库认证后可调用 `GET /:id/head`、`GET /:id/versions`、`GET /:id/snapshots/:snapshotId` 和 `POST /:id/snapshots`。上传要求 `If-Match` 为当前快照 ID，空仓库为 `empty`。访问凭证放在 `Authorization: Bearer` 头中。

稳定失败类别包括认证失败、版本冲突、格式不支持、完整性失败、数据超限、限流、本机版本变化及事务恢复待处理。错误响应不复制远端内容或底层数据库异常。

```powershell
node --test test/cloud-config.test.mjs test/cloud-config-boundaries.test.mjs
corepack pnpm run check
corepack pnpm test
corepack pnpm run test:ui
corepack pnpm run test:ui:cloud
```

测试只使用临时数据目录、合成凭据、回环 HTTP/SSH 服务，同时验证私网 HTTP 地址范围、公网 HTTP 拒绝和重定向限制。
