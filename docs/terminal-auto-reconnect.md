# 终端自动重连

## 使用体验

客户端运行期间，已经打开的人工终端遇到意外断线后，复用现有 SSH 连接管理器恢复连接，再在原标签中建立新 Shell。无需返回详情或再次确认。工作区显示真实重试次数、等待时间和耗尽状态，支持直接「立即重试」或「重新连接」。

- 意外中断时自动重连。主动「断开连接」期间不重试；用户重新连接同一服务器后，恢复断开前仍活动或等待恢复的终端。已经正常退出 Shell、结束会话、关闭标签或停止恢复的终端不重开；连接配置变化或身份校验失败仍停止恢复。
- 「停止恢复」只停止当前终端；不会主动断开共享 SSH 或改变文件传输任务。其他终端按队列继续恢复，当前可见标签优先。
- 重连保留有界历史文字（最多 5000 行、512 Ki 个 UTF-16 代码单元），重置终端控制状态，再显示新会话分隔线。旧文字按当前主题重新显示，不保证保留旧 ANSI 配色或全屏应用画面。
- 恢复不抢走其他控件的焦点。断线期间可查看历史，输入和粘贴暂停；待确认粘贴及旧输入不会自动发送到新会话。
- 新 Shell 使用服务器默认登录目录。文件树的浏览位置不代表 Shell 工作目录，不自动发送 cd 或其他人工命令。
- 旧命令的运行结果不能由重连判定，也不会重放旧命令。需要保持远端进程的工作另行使用适当的会话管理方式。
- 应用或窗口关闭后不自动恢复会话。上传与下载沿用各自的中断、暂停和恢复规则。

## 实现边界

SSH 重试仍由 EnvironmentConnectionManager 统一拥有，沿用 1、2、5、10、30 秒的等待间隔。等待时间不包含连接尝试自身耗时；网络变化和唤醒沿用现有通知机制。状态快照中的可选 reconnect 字段描述 waiting、connecting、exhausted、attempt、maxAttempts、nextRetryAt 和 pluginInstanceIds；不将其他插件的重试误显示为当前服务器断线。

PTY 打开在 Renderer 内串行排队，开始前再次检查标签、连接和请求代次。单次连续不稳定期间最多自动打开三次，失败间隔为 1、3 秒；成功稳定 30 秒后清零。恢复失败保留手动入口，不无限循环。仅终端通道失败时复用当前 SSH，不重新连接共享传输。

桌面 IPC 增量：

- serverTerminalRead 在排空输出后返回 closeReason 和 recoverable。未知通道关闭默认不自动恢复；仅同一轮关闭事件中收到明确 SSH 丢失通知时才授予恢复资格，正常退出始终不授予。用户主动断开返回 user-disconnected，仅保留原活动或待恢复会话的资格；必须等同一服务器重新连接后才允许打开。配置变更、应用关闭等其他系统断开不授予资格。
- serverTerminalOpen 可选 recoveryOf 指向原会话。后端验证相同 owner、三层作用域、标签、连接配置指纹及可恢复状态。恢复失败保留原记录供有限重试，成功后释放旧记录。
- serverTerminalClose 撤销原会话的恢复资格，并结束由其派生的在途恢复；迟到结果不会复活已结束的标签。
- SSH 主机身份确认复用现有连接确认组件。MCP 不增加终端 API，不改变凭据、主机校验、Agent 命令确认和文件变更确认边界。

## 验证

使用模拟通道、连接运行时和本地 Electron 夹具，不连接真实基础设施：

- 后端：跨窗口/标签/配置拒绝恢复；事件乱序；正常退出；主动断开后重连只恢复活动标签；断开期间停止恢复；配置变更撤销资格；恢复失败重试；在途取消；八标签恢复及会话上限。
- 连接管理：真实等待时间、次数及耗尽状态；认证错误停止；主动断开取消定时器。
- Renderer：当前标签优先；不重放待确认粘贴；不抢焦点；全屏状态清理及历史保留；停止单个恢复；单通道失败不触发 SSH 重连；工作区直接重试。
- 原有终端、上传下载、IPC 和连接回归继续执行。打包烟测检查 recoveryOf 的参数边界。
