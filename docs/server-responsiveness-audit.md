## 范围与约束

- 仅连接用户指定的一台服务器，不在仓库保存目标地址、凭据、服务器输出、文件内容或容器标识。
- 只读阶段读取目录、系统文件、监控、服务状态、journal 和容器信息；交互阶段使用禁用历史和启动配置的临时 PTY；后续变更阶段只处理本次随机目录中的合成文件，已完成清理。没有修改服务器原有文件或既有服务；服务控制仅使用本次随机名称的临时服务与定时器，已停止并核实回收。没有变更既有容器。
- 使用真实运行时与服务模块；目录、文件变更、传输与终端专项还覆盖真实可见 Renderer、preload 及生产文件 IPC，文件变更通过真实确认对话框提交。MCP 专项另外覆盖源码及包内 stdio MCP、带认证的 Broker、V2 服务、真实 SSH 和隔离项目的正式审计落盘。连接配置仍在内存，连接快照由测试适配器提供，审批由隔离驱动提交；不代表已安装客户端、完整桌面连接管理或整个工作区的可见验收。
- 保留主机指纹校验、连接代次、作用域、一次性确认、文件状态校验、读取上限与审计调用。
- 初次未知指纹被拒绝，再把观察到的指纹固定在本次内存配置中连接。这是首次使用信任，不是独立身份验证。

## 已定位的问题与修复

### 重复建立 SFTP 通道

原有目录读取即使使用目录快照，也会新建 SFTP 通道再校验目标。实测常见通道建立耗时约 24–36 ms，首次建立偶有更长等待。

这一早期批次先只在同一 SSH 连接内复用人工目录读取的空闲通道：每次操作独占，最多保留一个，空闲 30 秒释放（最初为 5 秒，后续停顿专项调整）。失败、取消、远端关闭、断线重连均淘汰旧通道。每次请求仍校验目标路径；当时 Agent 读取和变更通道维持原有生命周期；后续桌面预览与属性也已纳入复用，当前范围见“预览与属性复用空闲通道”一节。

同时通过 ssh2 的 setNoDelay(true) 关闭客户端小包合并等待。该设置减少交互式小请求的额外等待，不改变鉴权或服务器配置。

### 并发预览嵌套排队

两个文件预览会分别占住一个受限读取名额，再申请第二层读取名额。在每插件并发上限为二时，两者相互等待；真实测试观察到超过 3 秒仍未返回。

现将路径检查与内容读取放在同一个受限读取会话内，保留读取前后的链接目标检查、内容范围与文件身份检查。真实并发复测约 123 ms 返回，协议回归确认只使用两个会话。

### 目录树重复排序

展开、收起、加载状态变化会对所有展开分支重新过滤和自然排序。现在按不可变条目数组复用展示顺序及隐藏文件视图；刷新、分页、链接解析替换条目数组时重新计算，WeakMap 不长期保留被移除的目录。

合成负载为 25 个目录、5,000 条记录、300 次更新。同进程比较旧计算中位数 4.7662 ms、P95 6.8934 ms；复用后中位数 0.0010 ms、P95 0.0023 ms。这只测过滤与排序，不能代表网络、React 提交或绘制耗时。

### 传输开始后仍等待空闲轮询

真实下载检查通过后，进一步测量了前端“任务已能返回完成状态，但界面多久才显示完成”。原轮询在空闲时等待 1,500 ms；新下载加入队列后没有唤醒原计时器，因此小传输可能继续显示等待。

现在由“是否有活动任务”和工作区可见性驱动查询：新任务或工作区重新显示立即查询，活动期间每 250 ms 更新；可见空闲时仍为 1,500 ms，隐藏空闲时仍为 4,000 ms。原版本号和卸载检查继续阻止迟到查询覆盖当前状态。

同一 Electron 场景在空闲查询刚完成后点击下载，模拟文件在下一次状态查询时完成。三次基线为 1,505.5 / 1,501.0 / 1,505.6 ms；修复后为 9.4 / 9.8 / 16.4 ms。此数据覆盖点击到 DOM 完成状态提交，不包含真实下载时间，也不表示可见窗口的绘制延迟。原生窗口隐藏且已禁用后台计时器节流。

## 可见终端与连续缩放优化

新增 scripts/server-live-terminal-ui.mjs 与 scripts/server-terminal-interaction-ui.cjs，使用可见 xterm、真实 preload、生产终端 IPC、ServerWorkspaceManager 和授权主机的真实 PTY。仅为本次新会话替换 Shell 启动参数：禁用历史、启动配置和既有 readline 输入配置，使用固定测试提示符。每段页面输入都必须逐字匹配驱动预先登记的内容，只执行合成 printf 输出、stty size 和退出；其他工作区服务仍使用合成数据。

优化前连续缩小窗口时，本地 FitAddon 与远端尺寸通知一起等待 80 ms 的尾随防抖。连续事件会反复推迟处理，12 次采样只有两个不同的终端宽度，终端内容超过容器的最大宽度为 171 px。

现在本地 fit 合并到下一帧；远端更新仍按 80 ms 时间窗口合并，慢请求期间串行发送且只保留最新尺寸，已同步的相同尺寸不重复发送。取消或换会话使旧尺寸失效，卸载清理排队；发送前仍检查可见性、连接状态和确切会话。参考 [xterm 尺寸 API](https://xtermjs.org/docs/api/terminal/classes/terminal/#resize)关于限制尺寸更新频率的建议，保留远端合并并使本地画面及时适配。

scripts/server-terminal-theme-ui.cjs 观察实际样式节点并检查主题及无障碍输出：旧构建切换四次标签产生 16 次配色样式重写，新构建为 0 次；真正切换明暗主题产生 8 次更新，前后台两个终端均更新，两个无障碍文本层保留。该行为回归已加入完整服务器 UI 烟测，也可以单独执行；它证明重复工作被移除，不代表可见长帧已经全部消失。布局隔离实验没有取得有效完整数据，未加入产品样式。

### 组网目录协议调度

增加 --directory-protocol 诊断参数，在同一只读探针中记录 OPENDIR、READDIR、CLOSE、LSTAT 和 REALPATH 的起止时间、在途数、条目数量与 EOF 状态。每个测量步骤最多保留 300 条记录，不输出请求参数、目录内容、错误正文或凭据；原始样本只在当前诊断会话内保存。

原实现已有四个并发 READDIR，但使用 Promise.allSettled 等整批返回。本轮实际样本中，同批前两个请求约 378 ms 完成，后两个约 756 ms 完成；空闲位置因此额外等了约 378 ms 才补发。现保持首次单页读取，后续改为四个独立读取循环，完成一个即补发一个；按请求顺序合并乱序响应，条目上限、前后路径验证和快照规则保持不变。

| 操作 | 原批次调度 | 持续补发 | 结论 |
| --- | ---: | ---: | --- |
| 同批较快请求完成到补发 | 约 378 ms | 约 0–0.1 ms | 已消除整批等待，协议轨迹和本地慢页用例均验证 |
| 系统命令目录完整读取 | 4,562.8 ms | 4,682.9 ms | 没有测得整体提速；网络及收尾等待影响总时间 |
| 其中目录枚举 | 3,046.1 ms | 3,120.5 ms | 包含打开、数据页、EOF 和关闭句柄，不是纯服务器处理时间 |
| 同目录快照读取 | 755.1 ms | 780.8 ms | 不枚举，仍校验路径；同期单次协议往返由约 377 ms 变为约 389 ms |

上述两轮各通过 10 项检查、2 项审计调用，所有快照内容与原页一致。持续补发在接近目录末尾时可能先于 EOF 回调再发出读取；这些已发送请求必须排空，不能为了更快返回而遗留请求或跳过 CLOSE。本轮还尝试下一事件循环再补发，三次完整读取为 7,333.8 / 5,719.8 / 6,117.7 ms，快照为 720.1 / 696.6 / 2,270.1 ms，8 项检查通过，但无法证明该尝试有收益，已从生产实现撤除。该批包含明显链路波动，不用于计算优化比例。

本地真实 SSH/SFTP 用例先验证旧批次调度会卡在未返回的一页，再验证持续补发、数据页晚于 EOF、失败时等待其他在途响应、超过一万条时有界截断和在途取消。最终输出顺序、无遗漏/重复、最多四个在途请求、关闭前排空，以及失败/取消后不复用通道均通过。Agent 的目录读取路径未改动，未降低路径、作用域、确认或审计约束。

参考 WinSCP 的有界请求流水线与目录缓存思路。其目录实现将后续 READDIR 与当前页处理重叠，不能据此声称与本产品的四路补发相同；本产品仍等待句柄关闭完成再发布结果。当前保留的是有证据的局部调度改进，整体延迟和可见流畅度仍需继续验证。

### 目录关闭与路径复核重叠

继续后台分析发现，目录页全部返回以后仍串行等待 CLOSE，再执行完整路径复核。现仅在人工目录快照的首次扫描中重叠这两步：所有 READDIR 排空后发出关闭请求，同时启动原有的路径复核，两者都成功后才能交付条目、更新快照或归还通道。不支持该内部回调的适配器继续执行原有串行复核。

安全与一致性边界：未省略任何路径、类型、连接、配置或窗口代次校验，未改变 LSTAT 和 REALPATH 的内部先后顺序。CLOSE 失败或路径复核失败仍拒绝结果；若关闭响应晚于整轮路径复核，则关闭后再复核一次，避免交付长时间等待前的路径状态。取消仍终止当前读取通道，旧响应不能恢复快照。公共 IPC/MCP 参数、确认和审计不变。

本地真实 SSH/SFTP 新增七项收尾行为验证：两种完成顺序均不提前发布，两侧各自失败均不缓存或复用通道，窗口关闭和目录链接换目标后拒绝迟到结果，以及校验已完成而 CLOSE 长时间未返回时再次复核并拒绝失效路径。最初四项用例在串行实现中无法进入并行状态；修改后通过。另修正上一批条目上限测试的时序假设，以最终请求总数和结果上限验证有界性，不再把服务端已发送误当作客户端已接收。

--compare-finalize 在同一 SSH 连接内先预热，再按“串行、并行、并行、串行、串行、并行”交错取样；串行对照仅在探针中省略内部回调，由快照层执行完整串行复核。每次完整读取后还校验快照内容一致，全程只读。协议计时确认每次收尾均发生在最后一个 READDIR 返回之后。

## 目录刷新队列与工作区隐藏

后台协议优化之后，继续检查 Renderer 在慢目录请求尚未返回时的行为。原刷新队列固定保存开始时的展开分支，根目录返回后仍会读取已经收起的分支；返回服务器详情并保留工作区时也会继续补发。链接元数据完成后释放并发位置，原逻辑可能在工作区隐藏期间启动下一页；迟到的快照过期错误还可能直接触发隐藏目录重读。

新增 scripts/server-directory-lifecycle-ui.cjs 通过实际 React Renderer、preload 和测试 IPC，使用合成目录及可控制的延迟响应验证，不连接真实服务器。旧 Renderer 上先复现收起分支的问题：根目录等待期间收起两条分支并选择根目录，仍发送四个目录请求；修复后只发送根目录与仍展开分支两个请求。此项比较的是请求数量，不是可见响应速度。

刷新队列现在在开始每个后续请求前读取当前分支集合；工作区隐藏使旧刷新批次停止补发。快速返回时等已经发出的请求收尾，在 React 提交最新目录状态后才重新计算需要补齐的过期分支，避免重复读取刚完成的根目录。分支集合按现有状态记忆，终端等无关渲染不会每次重新遍历全部目录行。

链接补齐仅在工作区显示时启动新请求。隐藏期间已有查询返回过期或失效时，保留错误并将该目录标记过期，不立即重读；返回后继续执行原有远端校验。普通刷新和链接补齐分别保留最多两个请求的原有限制，已经发出的读取仍正常收尾，没有扩大读取权限、增加 IPC 参数或改变文件确认。

隐藏窗口专项五个场景全部通过：收起待刷新分支、返回详情后停止补发、请求未结束即快速返回、链接查询暂停与恢复、隐藏期间迟到的快照失效及返回重读。总计 26 个目录接口请求，其中 7 个链接查询，链接页并发峰值为 2；专项断言原生窗口未显示，0 Renderer 错误、0 外部页面请求。缓存年龄场景只推进 Renderer 的 Date.now，其余 Promise 与 IPC 调度真实运行；该专项不是远端慢链路吞吐或可见帧性能测量。

参考 [VS Code TreeView](https://code.visualstudio.com/api/references/vscode-api#TreeView)提供的可见性、展开与收起事件，以及 [Page Visibility API](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)减少不可见页面无用请求的原则。本改动使用产品现有的工作区可见状态，不把浏览器 visibilityState 当成原生窗口实际可见的证明，也不暂停用户已经开始的传输。

### 隐藏期间上传完成的目录更新

继续检查传输与目录联动：原 refreshEpoch effect 不检查工作区可见性。两批上传在返回详情后完成时，即使没有继续浏览文件，也会分别读取当前路径和两个上传目录；隐藏窗口回归在旧 Renderer 上稳定记录四次目录请求，其中根目录重复两次。

scripts/server-directory-lifecycle-ui.cjs 新增两场景：隐藏期间连续两批上传完成；根目录刷新尚未返回就隐藏、完成上传并快速返回。两场景均为隐藏期间零目录请求，返回后各一次根目录及两个受影响分支读取，未改变的分支不重读；迟到旧响应不会抹去过期状态。合并原五场景后七项通过，共 37 次目录请求、其中 7 次链接查询、链接页并发峰值 2，原生窗口保持隐藏，0 Renderer 错误、0 外部请求。这是请求生命周期回归，不是当前组网连接的可见流畅度验收。

随机二进制接收量在压缩后由约 8,403,312 增至 8,407,568 字节，上传量由 8,424,272 增至 8,428,192 字节，未取得带宽收益；测得读写时间增加数倍，上传期间事件循环延迟也更高。重复文本能大幅缩小，但耗时并非每个样本都降低。结合前一轮目录接收量约减少 75% 的证据，决策是不把压缩全局设为默认；保持现有配置，避免将目录优化的成本转嫁给二进制传输。成熟工具 [WinSCP](https://winscp.net/eng/docs/ui_login_ssh)提供独立压缩选项，未来若引入按连接选择，也需明确适用网络与传输负载，而非由单一目录样本自动开启。

## 目录路径检查流水线及失败通道回收

继续测量当前组网连接时，目录读取前后以及每次续页均需检查路径。原实现按 LSTAT 响应后再发送 REALPATH 串行执行；两项请求参数均为同一已规范化路径，真实路径结果不依赖属性响应。参考 [WinSCP 的有界属性请求队列](https://github.com/winscp/winscp/blob/master/source/core/SftpFileSystem.cpp)减少等待的做法；[SFTP v3 草案的请求同步与重排规则](https://datatracker.ietf.org/doc/html/draft-ietf-secsh-filexfer-02#section-6.1)允许多个请求在途，同时要求同文件请求按接收顺序处理。该参考是协议草案，不是已发布 RFC，也不把成熟工具的队列实现当成本产品安全验证的替代。

该早期路径流水线批次的人工目录会话依次发出 LSTAT 和 REALPATH，无需等待首个响应后才发第二个；两者都收尾才合成路径结果。属性错误沿用原错误映射；真实路径失败仍返回不可解析状态，由目录解析拒绝使用。当时普通文件读取、Agent 路径检查以及上传和确认前置条件仍使用原串行路径；后续桌面预览的路径及正文末次复核另有流水线改动，详见后续专项。该早期批次没有增加公共参数。目录扫描前后、续页、链接目标及关闭迟到时的再次复核全部保留，不跳过作用域、连接代次或窗口校验。每条路径最多两个协议请求在途；链接解析仍最多八条路径，因此该阶段至多十六个属性协议请求，READDIR 的四请求上限不变。

新增 test/server-workspace-path-pipeline.test.mjs 的七项真实回环 SSH 回归，覆盖两种响应顺序、缺失与权限拒绝、真实路径失败、取消后的迟到响应与同连接恢复，以及普通读取保留串行行为。旧源码在同时在途的断言上失败，修改后通过。原目录集成夹具延迟执行 LSTAT 时允许后来的同路径 REALPATH 先执行，和协议处理顺序不符；调整为排在被延迟的属性操作后处理，原路径变化拒绝码及不发布旧快照的断言均保留通过，没有把断言放宽为任意失败。

错误与取消回归还发现，旧实现只发送通道关闭，池记录需等远端关闭通知才移除；对不及时确认关闭的服务端会累积已不可借用的记录。现在通过 SftpReadPool.discard 在本地结束操作时移除记录并发送原有关闭，迟到关闭仍负责收尾监听器。两种属性失败及取消的真实协议回归在该修复前均因记录残留失败，修复后确认池清空、旧通道不复活、共享 SSH 可继续使用。路径、目录、上传提交和池专项共 115 项通过。

### 组网目标状态与连续展开的读取队列

### 连接取消与代理交接

本地回环复现了三个等待空档：地址解析、HTTP CONNECT 和 SOCKS5 握手挂起时，取消后 400 ms 内均未结束。现在每次 Server 连接持有内部取消控制器，覆盖凭据加载、解析、VPN 路由验证、TCP 和代理握手；取消、断开或被新尝试取代后，不再继续尝试候选地址或启动 SSH。旧尝试仅释放自身 socket 与诊断配置，成功连接保留原 attemptToken，使过期清理不能切断后来的连接。主机指纹、代理认证、VPN 路由要求和作用域不变。

独立复审另复现了代理成功后的首包丢失：将代理响应和合成 SSH banner 放在同一包内，消费者晚 30–40 ms 接手时，原实现可能丢失 banner。Server 现在显式请求暂停交接，HTTP 保留 CONNECT 后的余留字节，SOCKS 接住依赖库在下一轮重放的数据，再交给 ssh2 主动恢复读取。createProxySocket 默认行为及原有 HTTP/SOCKS 透明回环测试保持；本地覆盖带认证的延迟消费、握手拒绝、提前关闭、超时及响应上限。

本次清理产品创建的监听器、计时器和连接；底层解析、凭据读取等不能原生取消的操作可能继续完成，但迟到结果不能发起网络连接。当前 socks 依赖自身仍有一个 unref 握手计时器，它到期前可能保留内部状态；未修改依赖或重写代理协议，不能声称其内部计时器全部即时释放。

本地连接聚焦 71 项通过，另经独立复审验证延迟交接与整体关闭。closeAll 在调用时快照在途尝试并取消，收尾只清理仍属于原尝试的条目，迟到 DNS 和旧断开不能影响后来显式建立的新连接。

真实 --connection-cancel 后台只读专项 8 项通过、0 失败、4 项内存审计调用：预先取消不创建 SSH 客户端；实际握手阶段取消后 0.7 ms 结束等待，随后固定指纹重连、属性读取和最终断开通过。握手前等待为该步骤总耗时的一部分，不能把 0.7 ms 当成完整连接耗时；本批固定指纹连接约 16.3 秒、恢复重连约 3.7 秒，仍反映链路明显波动。真实复杂代理部署尚未覆盖，不用本地回环结果代替。全程不创建或变更远端资源。

### 搜索完整性、UTF-8 分页与显式刷新

本地发现并修复两个会产生误导结果的问题。内容搜索原先把每个 1 MiB 块分别解码；中文或四字节字符跨边界时可能漏掉匹配，并返回 truncated:false。现在在原始已校验字节上使用流式 UTF-8 解码，扫描预算和读取前后校验不变，旧自定义 Runtime 没有 readBuffer 时保留原兼容入口。显式目录刷新原先可能加入刷新前的在途读取，拿到旧清单；现在等待旧请求收尾后重新读取，同目录并发刷新合并，新刷新队列最多 32 项。没有修改 MySQL 元数据缓存，也没有通过额外并发掩盖等待。

普通文件与登记日志的文本页现在只返回完整字符，实际 endByte 与返回内容一致。预算不足以容纳首个完整字符时，已有 INVALID_ARGUMENT 提供 minimumBytes 和 suggestedValue，调整预算后保留数字 cursor 重试；不会返回空页和不前进游标。配置分页也采用同样的小预算错误规则。有效 UTF-8 分页保持正文完整；非法字节沿用替换字符语义，替换后的正文仍受预算限制，返回的字节游标可继续。尾读跳过窗口开头被截断的字符，报告实际起点。原始 READ 不扩大预算，二进制读取、增长边界和 stat/path 校验保持。

新增本地回归共 52 项：搜索/刷新 10 项，真实 SFTP UTF-8 分页 24 项，真实 SFTP 链接及权限边界 18 项。后者覆盖单点、双点和祖先循环，Agent 不递归进入链接目录或打开链接文件；显式链接操作只读取允许的目标层级。服务端循环解析采用本地夹具的 16 次上限，客户端另检查访问路径、请求数量和时限；不能把夹具上限当作真实服务器配置。LSTAT、STAT、OPENDIR、READDIR、OPEN、READ 权限拒绝后，名额、句柄和失败通道回收及恢复通过。
